# План рефакторинга конвейера классификации оттока

Исходная основа — notebook лабораторной 6.1, признаки HW5 и метка `churned` из синтетических данных TDG. Цель — самостоятельный воспроизводимый CLI с сохранением результатов исходной модели.

1. Перенести загрузку, разбиение, обучение и оценку в функции `pipeline.py`.
2. Вынести пути, список признаков, параметры модели, разбиение и порог в `config.json`.
3. Сохранить полный sklearn Pipeline и добавить логирование, manifest и безопасную перезапись артефактов.
4. Включить полные входы, их контрольные суммы и исходные функции для сравнения.
5. Проверить совпадение метрик, загрузку модели, повторный запуск и обработку ошибок.
6. Зафиксировать зависимости и подготовить Docker-запуск с каталогом результатов на хосте.
7. Описать запуск, архитектуру, изменения и ограничения оценки.

Конфигурация по умолчанию сохраняет RandomForest, десять исходных признаков, заполнение нулями, StandardScaler, стратифицированное разбиение 60/20/20, seed 42 и порог 0.5. Преобразования обучаются только на train. Постановка остаётся ретроспективной классификацией; оценка будущего оттока требует отдельного временного протокола.

Результаты выполнения приведены в [отчёте](../../refactoring_report.md) и [журнале эксперимента](../../experiments/001-refactoring-equivalence.md).
