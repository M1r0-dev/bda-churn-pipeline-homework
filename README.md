# Конвейер классификации оттока

Учебный рефакторинг в воспроизводимый CLI: загрузка готовых признаков, проверка данных, стратифицированное разбиение, обучение RandomForest, оценка и сохранение полного sklearn Pipeline. Реализация — [pipeline.py](<pipeline.py>), параметры — [config.json](<config.json>).

**Это ретроспективная классификация `churned`, не честный прогноз будущего оттока.** Признаки могут отражать последствия уже произошедшего ухода (temporal hindsight). Обучение преобразований только на train устраняет межвыборочную утечку fit, но не исправляет временную постановку задачи. Высокая AUC не доказывает качество будущего прогноза; подробнее [протокол оценки](<docs/evaluation_protocol.md>).

## Происхождение и данные

Основа проекта — notebook лабораторной 6.1 и десять признаков HW5. Для сравнения в репозитории сохранены [исходные функции](<provenance/original_functions.py>), [описание признаков](<provenance/features_report.md>) и [метрики исходной реализации](<provenance/baseline_metrics.json>).

В репозиторий включены **полные синтетические таблицы TDG**:

- [churn_features.parquet](<data/churn_features.parquet>) — 198 578 абонентов, ключ и 10 признаков;
- [churn_truth.csv](<data/churn_truth.csv>) — 200 000 синтетических абонентов; используется только `churned`;
- все строки признаков имеют метку, 1 422 дополнительные строки эталона не используются;
- генератор TDG 1.0.0, уровень S, seed 20260827; окно признаков `[2025-11-30, 2025-12-30)`.

Состав, ограничения популяции и происхождение: [описание данных](<data/README.md>), [SHA-256 входов](<data/source_manifest.json>), [паспорт TDG](<provenance/tdg_passport.json>). Повторно генерировать сырые CDR или обращаться к внешним каталогам HW4/HW5 не требуется.

## Установка и запуск

Все команды ниже выполняются **из корня репозитория**: в исходной учебной директории это `lab2` (из родительского каталога выполните `cd lab2`), после клонирования — `bda-churn-pipeline-homework` (выполните `cd bda-churn-pipeline-homework`). Требуются Python 3.11 с модулем venv и pip; CPU достаточно, GPU/API-ключи не нужны.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
python pipeline.py --config config.json
```

Версии основных и транзитивных зависимостей зафиксированы в [requirements.txt](<requirements.txt>). Проверенное окружение: CPython 3.11.18, Linux x86_64. Без активации venv можно использовать `.venv/bin/python` вместо `python`.

```bash
python -m unittest discover -s tests -v
```

Набор включает unit-, контрактные и full-data проверки по публичному baseline; тесты изолируют свои выходы во временных каталогах. При ошибке выполнения CLI пишет traceback в лог/stderr и возвращает 1; ошибка аргументов argparse возвращает 2, успешный запуск — 0.

## Конфигурация и обработка

В [config.json](<config.json>) пути к входам и каталогу результатов разрешаются **относительно самого конфига**, не текущей директории. Разделы:

| Раздел | Назначение |
|---|---|
| `data` | Пути Parquet/CSV, ключ, метка, список и порядок числовых признаков (`feature_columns`) |
| `preprocessing` | `test_size=0.4` — весь holdout; `val_size=0.5` — доля validation внутри holdout; seed 42; заполнение 0 |
| `model` | RF: 100 деревьев, depth 10, min split 10, min leaf 5, balanced, seed 42, n_jobs 4 |
| `evaluation` | Фиксированный порог 0.5, без подбора по test |
| `artifacts`, `logging` | Каталог, имена выходов, уровень/формат лога |

`data.feature_columns` — единственный источник списка и порядка признаков для всех этапов и артефактов. По умолчанию используются десять признаков HW5; для выбора подмножества, перестановки или добавления числовой колонки из входного Parquet достаточно изменить конфиг. Список должен быть непустым, без дубликатов, ключа, метки и колонок из `excluded_columns`. Менять Python-код не требуется.

Отбор по именам → приведение числовых nullable-колонок к float64 → ±inf в NaN → заполнение константой 0 → StandardScaler → RandomForest. Весь Pipeline обучается только на train; validation/test проходят только преобразование и оценку. Идентификатор и постфактум-поля не входят в whitelist. Строковые/object-признаки отвергаются, а не молча преобразуются в нули. Дубликаты/пустые ключи, непокрытые метками строки признаков, некорректная метка и конфликт путей приводят к отказу.

## Артефакты

Каталог `artifacts/` создаётся автоматически; имена задаются конфигом:

| Файл | Содержимое |
|---|---|
| `model.joblib` | Полный обученный Pipeline, включая отбор колонок, обработку пропусков и scaler |
| `features.json` | Список признаков в порядке, заданном конфигом |
| `metrics.json` | Threshold и ROC-AUC/F1/precision/recall для val/test |
| `manifest.json` | SHA-256 входов, кода и конфига; версии среды; параметры; размеры сплитов; reload-проверка |
| `splits.csv` | `subscriber_key,split` для всех 198 578 строк признаков |
| `pipeline.log` | Этапы, длительность, предупреждения и ошибки; перезаписывается |

Каждый запуск **переобучает**, кеша нет. Пять содержательных файлов заменяются по одному через временный файл и `os.replace`, без накопления копий. Это не транзакция всего набора: после сбоя возможен смешанный набор; повторите полный запуск. Параллельные писатели в один каталог не поддерживаются. Время находится только в логе; стабильность SHA проверена между одинаковыми запусками в одном окружении. При смене Python/пакетов manifest и сериализация могут отличаться.

Пример загрузки (только доверенный локальный joblib — не загружайте чужие pickle):

```python
import joblib
import pandas as pd

model = joblib.load("artifacts/model.joblib")
rows = pd.read_parquet("data/churn_features.parquet").head(100)
probabilities = model.predict_proba(rows)[:, list(model.classes_).index(1)]
labels = (probabilities >= 0.5).astype(int)
```

## Docker

Нужны доступный Docker daemon и сеть для первой загрузки образа/пакетов. [Dockerfile](<Dockerfile>) использует Python 3.11-slim с фиксированным digest, устанавливает pinned wheels и копирует полные входные данные. Контекст ограничен [.dockerignore](<.dockerignore>); результаты не встраиваются в образ.

```bash
docker build -t churn-homework:local .
mkdir -p artifacts
docker run --rm \
  --user "$(id -u):$(id -g)" \
  -v "$(pwd)/artifacts:/app/artifacts" \
  churn-homework:local
```

В образе рабочая директория `/app`, CMD — `python pipeline.py --config config.json`. Bind mount оставляет шесть результатов на host после удаления контейнера. Запуск от UID/GID host предотвращает root-owned файлы; каталог должен быть доступен этому пользователю на запись. Без `--user` образ работает от root. Команды рассчитаны на Linux shell; проверена платформа linux/amd64.

## Проверенные результаты

На полных данных при seed 42: train **119 146**, validation **39 716**, test **39 716**. Результаты сравнения с исходной реализацией приведены в [журнале эксперимента](<experiments/001-refactoring-equivalence.md>):

| Выборка | ROC-AUC | F1 | Precision | Recall |
|---|---:|---:|---:|---:|
| validation | 0.968909 | 0.677899 | 0.536835 | 0.919523 |
| test | 0.969582 | 0.688349 | 0.548513 | 0.923881 |

Метрики совпали с реально запущенным исходным baseline; вероятности после загрузки проверены на 39 716 test-строках с допуском 1e-12 относительно baseline. Два последовательных локальных CLI завершились с кодом 0, SHA пяти файлов совпали (лог исключён). Проверка от 2026-11-24: **63 теста, OK**; текущий Docker-образ собран и дважды запущен с volume от пользователя хоста. Метрики и пять артефактов совпали с локальным запуском. Подробности — в [отчёте](<refactoring_report.md>); [verification.json](<verification.json>) сохраняет результаты предыдущей версии от 2026-11-20.

Один train-label-only shuffle дал validation AUC 0.636593 и **не прошёл** ожидаемый диапазон 0.45–0.55. При независимом перемешивании train и validation меток AUC 0.498504; это не отменяет первый неуспешный sanity и не доказывает отсутствие временной утечки. Два одинаковых запуска — проверка инженерной повторяемости, не независимые seed и не оценка неопределённости.
