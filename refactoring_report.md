# Отчёт по рефакторингу

## 1. Исходная точка и допущения

Фактически использован локальный notebook лабораторной **6.1** и десять признаков **HW5**. В сохранённом выводе задания упоминается «ДЗ 5.2», однако отдельный однозначно установленный проект 5.2 отсутствует; принятие доступного notebook за основу — явное допущение. Исходные материалы сохранены локально без изменений; первоначальной Git-истории нет, поэтому история нового репозитория не выдаётся за историю оригинала.

Для проверяемого сравнения сохранены в репозитории [исходные функции](<provenance/original_functions.py>), [формулы признаков](<provenance/features_report.md>), [паспорт генератора](<provenance/tdg_passport.json>) и [baseline_metrics.json](<provenance/baseline_metrics.json>). Последний получен фактическим запуском архивных функций на полных входах, не переписан из outputs notebook. Границы данных и их SHA-256 находятся в [описании](<data/README.md>) и [source_manifest.json](<data/source_manifest.json>).

Задача — инженерная эквивалентность и воспроизводимая поставка, **не** улучшение модели. Сохранены RandomForest, десять исходных признаков, fill-0, StandardScaler, стратифицированные 60/20/20, seed 42, threshold 0.5. Это ретроспективная классификация `churned` с temporal hindsight, не честный прогноз будущих 30 дней.

## 2. Выделенные функции

Код перенесён из зависимых от состояния notebook-ячеек в [pipeline.py](<pipeline.py>):

| Контракт | Обязанность |
|---|---|
| `load_data(config) -> DataFrame` | Загрузка признаков и метки; валидация ключей, числовых колонок, whitelist и покрытия. Внутренний `_load_inputs` также возвращает паспорт входов для manifest |
| `preprocess(frame, config) -> dict` | Два стратифицированных разбиения; сырые X/y и соответствие ключей сплитам, без fit scaler |
| `train_model(X, y, config) -> Pipeline` | Обучение полного сериализуемого preprocessing + RandomForest только на train |
| `evaluate(model, splits, config) -> dict` | ROC-AUC/F1/precision/recall на val/test при заданном threshold |
| `run_pipeline(config_path) -> dict` | Чтение конфигурации, этапы, сохранение, reload-проверка, метрики/manifest |

CLI `python pipeline.py --config config.json` не требует ноутбука, персональных путей или внешней папки предыдущего ДЗ. Публичные инструкции — [README](<README.md>); схема — [architecture.md](<architecture.md>) и [HTML](<architecture.html>).

В отличие от сохранения отдельного forest и scaler в notebook теперь сохраняется единый Pipeline: выбор признаков по именам и cast к float64 → inf в NaN → SimpleImputer(constant=0) → StandardScaler → RF. Он принимает исходный DataFrame, отбрасывает лишние колонки и не зависит от порядка колонок. Object/string ML-колонки отвергаются: fill-0 относится к отсутствующим/нефинитным **числовым** значениям, а не к произвольному тексту.

## 3. Конфигурация и логирование

[config.json](<config.json>) содержит пути данных, ключ/метку, фиксированный список признаков, доли разбиения, seed, fill_value, параметры RF, порог оценки, имена артефактов и настройки logging. Неизвестные ключи, неверные типы/границы и изменённый whitelist приводят к понятной ошибке. Пути трактуются относительно самого JSON-конфига. `test_size=0.4` — доля всего holdout, `val_size=0.5` — доля validation внутри него, а не 50% всех данных.

Logging направлен одновременно в stderr и `artifacts/pipeline.log`; конфиг определяет уровень/формат. Регистрируются этапы, число строк/сплитов, длительность обучения, метрики и reload. Лог перезаписывается (`mode=w`), существующие root handlers заменяются (`force=True`). Ошибки исполнения CLI дают traceback и exit 1; ошибки аргументов argparse — exit 2. До открытия лога проверяются коллизии имён/путей, symlink и существующие hardlink aliases с входами/выходами.

## 4. Идемпотентность и её границы

Кеша нет: повторный запуск всегда обучает заново. Стабильные имена: `model.joblib`, `features.json`, `metrics.json`, `manifest.json`, `splits.csv` и `pipeline.log`. Пять содержательных файлов записываются во временный файл в том же каталоге, синхронизируются и заменяются через `os.replace`; временный файл убирается при ошибке. Время/длительность не входят в метрики и manifest, остаются в логе.

Manifest фиксирует SHA-256 данных, кода и конфига, версии Python/пакетов, признаки/параметры, размеры сплитов и результат загрузки модели. Вероятности RF для оценки/reload агрегируются в один поток: параллельное суммирование давало различия порядка 1e-16; обучение сохраняет `n_jobs=4`.

Это **атомарность отдельных файлов**, не транзакция всего набора. При падении между заменами возможны артефакты разных запусков; требуется повторить полный запуск. Одновременные писатели в одну директорию не поддерживаются. Между разными Python/версиями пакетов не обещаются одинаковые manifest/joblib, а fixed digest/pins не доказывают битовую идентичность Docker image.

## 5. Найденные сложности и исправления

1. **Происхождение и переносимость.** Вместо абсолютных персональных путей — относительный конфиг и полные входы в репозитории: 198 578 строк признаков и 200 000 строк синтетического эталона. Left join сохраняет порядок признаков и требует метку для каждой строки; лишние 1 422 строки эталона только регистрируются.
2. **Утечка признаков и сохранение preprocessing.** Whitelist применяется и при обучении, и внутри сериализованной модели. Идентификатор, метка, `churn_day_index` и прочие поля не могут стать X. Scaler/imputer fit только на train.
3. **Nullable numeric.** Review обнаружил допустимые pandas `Float64`/`Int64` с `pd.NA`, которые нельзя надёжно передать через прежний passthrough в numpy-обработку. Внутри selector добавлен стандартный `FunctionTransformer` с cast к float64; регрессионный тест проверяет этот вход.
4. **Безопасность выходов.** Дополнены `samefile`-проверки существующих hardlinks до truncation лога. Файлы модели/лога не должны затереть код, конфиг или входы.
5. **Docker volume и права.** Лог перенесён внутрь общего каталога artifacts. Реальный non-root запуск выявил source mode 0600 (exit 2); `COPY --chmod=644` сделал код/конфиг читаемыми. README рекомендует host UID/GID, чтобы не оставлять root-owned результаты.
6. **Изоляция тестов.** Full-data тест сначала писал в основной artifacts; исправлен на временный каталог. Контрольные CLI выполнены последовательно уже после изолированного набора тестов.
7. **Неверная научная интерпретация.** Train-only fit не исправляет hindsight исходной `churned`. Непрошедший train-label-only sanity не скрыт и не заменён утверждением «вся утечка исключена».

## 7. Архитектурная документация и остающиеся ограничения

[Mermaid](<architecture.md>) описывает источники, управление этапами и хранение. [HTML](<architecture.html>) создан archify со ссылками на committed source: автоматические validate/deliver/check/browser-check пройдены; визуальная perceptual-проверка не запрашивалась и не заявляется. Viewer chrome имеет английский fallback; содержание русское.

Повторные запуски при одном seed — не независимые эксперименты. Не оценивались доверительные интервалы, будущий target после cutoff, out-of-time качество или реальные клиенты. Для прогноза нужно заново определить исторически доступные признаки/целевой интервал и временное разбиение, а не просто изменить scaler. Публикация GitHub выполняется Lead после интеграционной проверки; сам этот отчёт не является доказательством уже состоявшейся публикации.
