# Отчёт по рефакторингу

## Исходная задача

Конвейер перенесён из notebook лабораторной 6.1 в самостоятельный CLI с JSON-конфигурацией, логированием и сохранением модели. Использованы десять признаков HW5 и полные синтетические данные TDG: 198 578 строк признаков и 200 000 строк эталона. Для каждой строки признаков есть метка; 1 422 строки эталона без признаков не участвуют в обучении.

Для сравнения сохранены [исходные функции notebook](provenance/original_functions.py), [описание признаков](provenance/features_report.md) и [исходные метрики](provenance/baseline_metrics.json). Происхождение и контрольные суммы входов приведены в [описании данных](data/README.md).

## Изменения

[pipeline.py](pipeline.py) содержит пять основных функций:

| Функция | Назначение |
|---|---|
| `load_data(config)` | Загрузка Parquet/CSV, проверка ключей и числовых признаков, объединение с меткой |
| `preprocess(frame, config)` | Стратифицированное разбиение train/validation/test и сохранение соответствия ключей выборкам |
| `train_model(X, y, config)` | Обучение полного sklearn Pipeline только на train |
| `evaluate(model, splits, config)` | ROC-AUC, F1, precision и recall на validation/test |
| `run_pipeline(config_path)` | Выполнение этапов, запись артефактов и проверка загрузки модели |

Вместо раздельных модели и scaler сохраняется единый Pipeline: отбор колонок по именам → приведение к float64 → замена бесконечностей на NaN → заполнение пропусков → StandardScaler → RandomForest. Модель принимает исходный DataFrame и сохраняет порядок признаков, заданный при обучении. Преобразования обучаются только на train.

Все параметры и пути вынесены в [config.json](config.json). **Список и порядок признаков задаются только в `data.feature_columns`** и используются при загрузке, разбиении, обучении и записи `features.json`/`manifest.json`. Можно выбрать подмножество, изменить порядок или добавить числовую колонку, имеющуюся во входном Parquet, без изменения Python-кода. Пустой список, дубликаты, ключ, целевая и явно исключённые колонки отвергаются. Конфигурация по умолчанию сохраняет десять исходных признаков.

Пути разрешаются относительно конфига. Ошибки данных и параметров сопровождаются понятными сообщениями; этапы и метрики записываются в stderr и `artifacts/pipeline.log`. Повторный запуск переобучает модель и заменяет файлы с теми же именами. Перед записью проверяется, что выходы не затрут входные данные, конфиг или код.

Результаты: `model.joblib`, `features.json`, `metrics.json`, `manifest.json`, `splits.csv` и `pipeline.log`. Manifest содержит контрольные суммы данных, кода и конфига, версии зависимостей и параметры запуска. [Dockerfile](Dockerfile) и [requirements.txt](requirements.txt) фиксируют среду; команды локального и контейнерного запуска приведены в [README](README.md).

## Возникшие сложности

Перенос из notebook потребовал заменить зависимость от состояния ячеек и локальных путей явными аргументами функций и путями из конфига. Для nullable-типов pandas добавлено приведение к float64 перед обработкой пропусков. При сохранении результатов учтены совпадения путей и жёсткие ссылки, чтобы запись лога не повредила входы. Для Docker обеспечены права чтения кода и конфига при запуске от пользователя хоста. Дублирующий список признаков в Python заменён чтением из конфигурации, а тестовые результаты изолированы во временных каталогах.

## Результаты

Для конфигурации по умолчанию сохранены RandomForest со 100 деревьями и глубиной 10, заполнение пропусков нулями, StandardScaler, seed 42 и порог 0.5. Размеры train/validation/test: **119 146 / 39 716 / 39 716**.

|---|---:|---:|---:|---:|
| validation | 0.968909 | 0.677899 | 0.536835 | 0.919523 |
| test | 0.969582 | 0.688349 | 0.548513 | 0.923881 |

Метрики совпадают с исходной реализацией. Тесты проверяют разбиение, обучение преобразований только на train, обработку NaN/inf и nullable-чисел, сохранение и загрузку модели, повторный запуск и защиту входных файлов. Дополнительные проверки охватывают изменение состава и порядка признаков через конфиг, включая новую числовую колонку и модель с единственным признаком.

Проверка от **2026-11-24**: прошли **63 теста**, локальный CLI и сборка текущего Docker-образа. Два последовательных запуска контейнера от пользователя хоста создали по шесть файлов; контрольные суммы пяти артефактов совпали между запусками и с локальными результатами. Метрики сохранились, загрузка модели проверена на 39 716 test-строках.

Результаты исходных локальных и Docker-запусков от 2026-11-20 сохранены в [verification.json](verification.json): 61 тест, два последовательных запуска с одинаковыми контрольными суммами пяти артефактов и совпадение вероятностей с исходником на 39 716 test-строках. Этот файл относится к указанной в нём версии кода. Результаты проверки после изменения конфигурируемости приведены в [журнале](experiments/001-refactoring-equivalence.md).

## Ограничения

Это ретроспективная классификация `churned`: признаки могут отражать последствия уже произошедшего ухода. Высокий ROC-AUC не подтверждает качество прогноза будущего оттока. Один контроль с перемешиванием только train-меток дал validation AUC 0.636593 вместо ожидаемых 0.45–0.55; отсутствие временной утечки не доказано. Подробности — в [протоколе оценки](docs/evaluation_protocol.md).

Использован один seed; доверительные интервалы и качество на будущих периодах не оценивались. Стабильность файлов проверяется в одной среде. Файлы заменяются атомарно по отдельности; после прерванного запуска требуется повторить конвейер. Одновременная запись нескольких запусков в один каталог не поддерживается.
